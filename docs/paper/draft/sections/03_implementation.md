# 3. Implementation

## 3.1 Reading MODFLOW 6 output

The code needs only MODFLOW 6 output, not the model's input files (Langevin et al. 2017). The binary grid file gives the cell connections of structured (DIS), vertex (DISV) and unstructured (DISU) grids. The flows come from the GWF budget files. The user saves them with SAVE_FLOWS in each package and SAVE BUDGET ALL in the OC file. A package that passes water to the water mover (MVR) writes two records per boundary, such as DRN and DRN-TO-MVR. Both are kept, since the cell budget closes only with both. The code also writes release points for PRT, the particle-tracking model built into MODFLOW 6 (Langevin et al. 2026). PRT works like MODPATH (Pollock 2016) but runs inside MODFLOW 6. The two methods can then be compared on the same problem (Section 5.3). Particles start where water enters the model through a source term. Each particle carries a weight, which is the flow of water it represents. Particle weights then add up to flows. <!-- src/gwsource/prt.py docstring (release points, face terms: particles of a flow assigned to one cell face (IFLOWFACE) start on that face; sentence cut in round 5 for length) --> When a particle passes through a cell with a sink, it loses the share of its weight that the sink takes from the cell's water. It carries the rest on. The destination is credited with its part. We refer to these as weight-losing particles. <!-- src/gwsource/prt.py docstring ("Weak sinks and the destination": d_j / O_j x W to the destination, keeps (1 - Snk_j / O_j) x W, computed along the PRT tracks) --> These particles treat weak sinks as gross accounting does (Section 2.3). Any difference from full mixing therefore comes from how water spreads between sinks: along particle paths, or by mixing in every cell.
